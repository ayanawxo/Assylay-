# Канат — перетягивание каната в браузере

Задание второго этапа отбора **Narxoz Incubator 2026** («Перетягивание каната»).

**Играть:** https://ayanawxo.github.io/Assylay-/
**Исходный код:** этот репозиторий. Приложение полностью статическое: HTML + CSS + JavaScript без сборки и без сервера.

---

## Что это

Двухмерная игра «перетягивание каната»: две команды, общий канат с флажком, граница победы с каждой стороны. Матч длится 60 секунд (настраивается: 45 / 60 / 90). Играть можно против компьютера трёх уровней или вдвоём на одной клавиатуре/одном телефоне.

Игра сделана для тех, кому нужна короткая напряжённая дуэль на одну минуту: школьники на перемене, студенты между парами, компания за одним ноутбуком. Главная идея — **это не соревнование в скорости кликов**. Побеждает тот, кто тянет в ритм, вовремя отдыхает и добивает соперника рывком в нужный момент.

## Чем отличается от «двух кнопок “Тянуть”»

Три связанных механики создают выбор в каждую секунду матча:

| Механика | Что делает | Зачем это игроку |
|---|---|---|
| **Выносливость** | Каждый тяг стоит 7 из 100. При нуле — «выдохся»: тяги слабеют до 30 %, пока не восстановишься до 20. | Нельзя тянуть без остановки. Кто спамит — проигрывает тому, кто отдохнул. |
| **Ритм** | Внизу экрана бегает курсор. Тяг в зелёной зоне даёт ×1.6 силы. Ритм общий для обеих сторон. | Меньше кликов — больше пользы. Точность важнее скорости. |
| **Упор** (удержание) | Пока держишь — тянуть нельзя, но силы восстанавливаются в 3 раза быстрее, а тяги соперника действуют лишь на 45 %. | Способ передохнуть, не отдав канат. Момент выхода из упора — тактическое решение. |
| **Рывок** | Тяг ×3 за 35 выносливости, перезарядка 4 с. Не проходит, если сил меньше 35. | «Ультимейт» для добивания выдохшегося соперника. Рывок в ритм — самое сильное действие в игре. |

Ограничение частоты (не чаще ~6 тягов в секунду) и обработка только перехода «отпущено → нажато» делают бесполезными удержание клавиши, автоповтор и «дребезг».

## Управление

| Действие | Игрок 1 (слева) | Игрок 2 (справа, режим «вдвоём») | Телефон |
|---|---|---|---|
| Тянуть | **A** (или Пробел) | **J** (или ←) | тап «ТЯНУТЬ» |
| Упор | держать **S** (или Shift) | держать **K** (или ↓) | удерживать «УПОР» |
| Рывок | **D** | **L** (или →) | тап «РЫВОК» |
| Выйти из матча | Esc | Esc | кнопка «✕ Выйти» |
| Реванш на экране результата | Enter / Пробел | | кнопка |

Раскладка клавиатуры не важна: используются физические коды клавиш.

## Условия победы

1. **По границе.** Флажок дошёл до линии соперника — мгновенная победа.
2. **По времени.** Время вышло — побеждает тот, на чьей половине флажок (если он не ближе 3 единиц к центру).
3. **Овертайм.** Если по истечении времени флажок практически в центре — 20 секунд овертайма с укороченной границей (±40 вместо ±100).
4. **Ничья.** Если и после овертайма флажок остался в центре (±1).

Действия до сигнала старта и после финиша не влияют на результат. Каждый новый матч начинается с чистого состояния.

## Режимы

- **Против компьютера** — лёгкий / средний / сложный. Бот действует только через тот же API, что и человек: тратит выносливость, ждёт перезарядку рывка, не может тянуть в упоре и не превышает лимит частоты. Уровни отличаются скоростью реакции, темпом, точностью попадания в ритм и тактикой (когда уходить в упор, когда тратить рывок, стоит ли тянуть в чужой упор).
- **Вдвоём на одном устройстве** — клавиатура A/S/D против J/K/L или два набора кнопок на телефоне.
- **Серии** — один матч, до 2 побед (из 3) или до 3 побед (из 5).
- **Ритм-тренировка** — 20 секунд, цель попасть в ритм максимальное число раз. Рекорд сохраняется.
- **Обучение** — 4 интерактивных шага (тяг → ритм → упор → рывок), каждый требует выполнить действие.

Локально сохраняются: имя, настройки, статистика побед/поражений по уровням, серия побед, точность ритма, рекорд тренировки, последние 50 матчей.

## Оформление и «монетизация» (тестовый режим)

В разделе «Оформление» три арены: «Школьный двор» (бесплатно), «Ночной стадион» и «Пляж» (Pro). Косметика никак не влияет на правила и силу. Кнопка «Открыть Pro (тест)» показывает явное предупреждение о тестовом режиме — **реальные платежи не выполняются**, флаг Pro сохраняется только в localStorage браузера. Это демонстрация модели «продаём оформление, а не преимущество».

## Технологии

- **Ванильный JavaScript (ES5-совместимый), HTML5 Canvas, CSS.** Ни фреймворков, ни сборщика, ни зависимостей во время выполнения.
- **Архитектура:** игровая логика полностью отделена от отображения.
  - `js/engine.js` — движок: состояние, действия, выносливость, ритм, физика каната, фазы матча. Не знает о DOM. Работает и в Node.js.
  - `js/bot.js` — компьютерный соперник (три уровня).
  - `js/render.js` — отрисовка сцены на canvas, темы оформления.
  - `js/input.js` — клавиатура и сенсорные кнопки с защитой от удержания.
  - `js/audio.js` — звук, синтезированный через WebAudio (без аудиофайлов).
  - `js/storage.js` — localStorage: настройки, статистика, история, Pro.
  - `js/app.js` — экраны, игровой цикл, HUD, обучение, серии.
- **Фиксированный шаг логики** (60 тиков/с через аккумулятор времени в `requestAnimationFrame`): скорость игры не зависит от частоты кадров и не ломается при переключении вкладки.
- **Адаптивность:** работает на десктопе (клавиатура) и телефоне (кнопки, портрет и ландшафт).

## Запуск локально

Нужен любой статический сервер (через `file://` тоже откроется, но лучше сервер):

```bash
git clone <url-репозитория>
cd <папка>
python3 -m http.server 8000
# открыть http://localhost:8000
```

Тесты движка и симуляция баланса (Node.js ≥ 14):

```bash
node test/engine.test.js   # 11 проверок: старт/финиш, лимит частоты, выносливость, упор, рывок, ритм, овертайм, reset, бот
node test/sim.js 200       # бот против бота: процент побед по уровням
```

## AI-инструменты и заимствования

- Код, графика (процедурная отрисовка на canvas), звук и тексты созданы в диалоге с **Claude Code** (Anthropic) по этому техническому заданию; баланс подобран по симуляции «бот против бота» и ручным тестам.
- Сторонние библиотеки, шаблоны и готовые ассеты **не используются**. Иконка — inline SVG. Шрифты системные.
- Для автотестирования интерфейса в процессе разработки использовался Playwright (в проект не входит).

## Известные ограничения

- **Нет онлайн-аккаунтов и сетевого мультиплеера.** Профиль, статистика и история живут в localStorage конкретного браузера; с другого устройства их не увидеть. Это осознанное ограничение статического хостинга без бэкенда.
- «Оплата» Pro — только тестовый режим.
- Физика каната упрощена (импульс + затухание), без симуляции провисания.
- На очень старых браузерах без `pointer events`/`WebAudio` сенсорные кнопки и звук могут не работать (Chrome/Safari/Firefox последних версий — ок).

## Возможное развитие

Комнаты для игры на разных устройствах (WebRTC/WebSocket с серверной проверкой действий), рейтинг, турниры между группами, командные матчи 2×2 с бонусом за синхронный рывок, кабинет организатора.
